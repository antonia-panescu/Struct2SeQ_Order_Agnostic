# Order-Agnostic Struct2SeQ SHAPE Training Handoff

## Goal

Continue the evaluated order-agnostic Struct2SeQ policy for **5 additional
episodes** using the combined secondary-structure and SHAPE reward from
Struct2SeQ-SHAPE.

The starting checkpoint must be the best order-agnostic checkpoint that was
used for evaluation, not the released left-to-right `Struct2SeQ.pt` checkpoint.
Model checkpoints and replay data are intentionally not stored in Git.

The existing five-episode configuration remains unchanged:

- `n_episodes: 5`
- `epochs_per_episode: 5`
- `learning_rate: 0.0001`
- `k_perm: 4`

An "episode" and a training "epoch" are different here. Each of the five
episodes contains five optimizer epochs over the replay data selected by the
existing training loop.

## Minimal code change in this repository

`run.py` now accepts:

```text
--shape-reward
```

Without this flag, training and evaluation retain the original
secondary-structure-only reward.

With this flag, every newly generated sequence is evaluated by both:

1. RibonanzaNet-SS, for exact per-position pairing correctness.
2. RibonanzaNet, for the predicted SHAPE profile.

A position receives reward 1 only when its secondary structure is correct and:

- a target-paired position has predicted SHAPE `< 0.25`; or
- a target-unpaired position has predicted SHAPE `> 0.125`.

These are strict inequalities and match the `Env_SHAPE.py` supplied by Shujun.
All other positions receive reward 0.

No optimizer, model architecture, replay loader, batching, checkpoint, resume,
or episode-scheduling behavior was changed.

## Ready path: generate fresh order-agnostic SHAPE replay

This path is supported directly by the code in this commit. It preserves the
same play-then-train procedure as the completed order-agnostic structural run,
but its environment is roughly twice as expensive because it runs both
RibonanzaNet models.

Run from a dedicated output directory so checkpoints, `tmp/`, logs, and stats
do not collide with another experiment:

```bash
accelerate launch \
    --mixed_precision bf16 \
    --num_processes "${NUM_PROCESSES}" \
    /path/to/Struct2SeQ_Order_Agnostic/run.py \
    --config /path/to/Struct2SeQ_Order_Agnostic/config_order_agnostic_5ep_from_s2s.yaml \
    --target_structure_file /path/to/top2M.csv \
    --order-agnostic \
    --shape-reward \
    --checkpoint /path/to/evaluated_order_agnostic_best_policy_network.pt
```

For fresh online SHAPE training, that output directory must not contain
completed structure-only replay from an earlier run. `--shape-reward` controls
newly computed rewards; it does not retroactively relabel rewards already saved
under `tmp/`.

The repository must contain or be given access to:

```text
weights/RibonanzaNet-SS.pt
weights/RibonanzaNet.pt
```

The GPU/process count is deliberately not fixed here. Set `NUM_PROCESSES` to
the actual allocation. Confirm whether the configured batch sizes are intended
as per-process or global values under the installed Accelerate configuration
before changing them. A larger GPU count should not automatically imply a
larger desired global batch.

## Shujun's precomputed replay archive

Shujun provided the original Struct2SeQ-SHAPE 240-nt replay at:

```text
/oak/stanford/groups/rhiju/sherlock/home/shujun/Ribonanza2/DQN_backup/backup/test3.tar.gz
```

He reports that it produces a directory named `tmp` after extraction. The Oak
filesystem was not mounted in the environment where this handoff was written,
so the archive layout and contents have **not** been verified here.

Using replay generated by the original left-to-right Struct2SeQ is valid
off-policy Q-learning. The order-agnostic trainer randomly permutes each stored
sequence and its positional rewards together. It is nevertheless an empirical
choice: the original replay covers the sequence distribution of the original
policy rather than the order-agnostic policy.

### Inspect before extracting or training

Run on a machine with Oak access:

```bash
tar -tzf \
  /oak/stanford/groups/rhiju/sherlock/home/shujun/Ribonanza2/DQN_backup/backup/test3.tar.gz \
  | head -100
```

Determine:

1. Whether paths are organized as `tmp/episode*/process*/...`.
2. Which replay episodes are included.
3. Whether records are consolidated `data.pt` files or legacy `.pkl` files.
4. The number of processes used to generate the replay.
5. Whether rewards are already the combined structure+SHAPE positional reward.
6. Whether every structure, sequence, and reward vector has length 240.

Do not assume that the number of replay-generating processes must match the
number of GPUs used for gradient training.

### Formats the existing loader understands

`RNADataset` currently understands:

1. Consolidated `data.pt` files containing:

   ```text
   structures
   sequences
   rewards
   ```

2. Legacy pickles containing a three-item record:

   ```text
   [structure_tensor, sequence_tensor, positional_reward]
   ```

If the archive already matches one of these layouts, prefer staging or
converting the archive around the existing loader instead of rewriting the
loader or training loop.

### Important current replay behavior

The existing `--skip-play` flag skips play only for the starting episode.
Automatic play skipping for consolidated replay requires the current
`data.pt`/completion-marker layout. Legacy pickles follow a separate fallback.

Therefore, do not launch a five-episode replay-only run until the archive has
been inspected. The collaborator's coding agent should make only the smallest
staging or invocation adjustment justified by the actual archive:

- extract into job-local or project scratch rather than the Git checkout;
- preserve the archive unchanged;
- select the intended five replay episodes;
- preserve the current cumulative replay semantics if the archive contains
  per-episode data;
- avoid rerunning either RibonanzaNet model when rewards are already present;
- avoid changing model, optimizer, or checkpoint code merely to accommodate
  file placement.

If the archived rewards are structure-only, they are not sufficient for SHAPE
training. They must be relabeled with RibonanzaNet SHAPE. If they are already
the Struct2SeQ-SHAPE combined rewards—as Shujun's message suggests—no oracle is
needed during gradient training. Passing `--shape-reward` would then matter
only for any fresh play or online test play performed by `run.py`; training
always consumes the reward stored in replay.

## Experiment-specific values to personalize

The collaborator or their coding agent must set these from the actual cluster:

- GPU/process count.
- Per-process batch sizes and desired effective global batch.
- Target-structure CSV path.
- Actual path to the evaluated order-agnostic best checkpoint.
- RibonanzaNet weight paths for online play/evaluation.
- Replay archive extraction/staging path.
- Which five archive episodes or shards constitute the intended replay run.
- Output, checkpoint, temporary-data, and W&B locations.
- Scheduler time limit and preemption/resubmission wrapper.

Do not use `weights/order_agnostic_policy.pt` blindly on another system: in the
original environment it is a machine-specific symbolic link. Transfer or point
to the real `best_policy_network.pt`.

## Preflight checks

Before a full run:

1. Confirm the checkpoint loads with only the expected relative-position bias
   keys initialized when applicable.
2. Confirm a small batch produces 240-length structures, sequences, SHAPE
   profiles, and rewards.
3. Confirm `--shape-reward` reduces an otherwise structurally correct reward at
   positions that fail the SHAPE thresholds.
4. Confirm all allocated processes enter play/training and write to the intended
   output directory.
5. Confirm resume finds the expected episode and checkpoint.
6. Record the Git commit, configuration, starting checkpoint, replay source,
   replay episode selection, process count, and batch sizes in the run log.
